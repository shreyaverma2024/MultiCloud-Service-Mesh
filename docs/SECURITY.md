# Security Model

## 1. Security goals

- No hardcoded secrets in source, tests, Docker images, logs, or browser assets.
- Separate secrets for separate purposes.
- Strong authentication on management and cache APIs.
- Application-level authentication for cross-cloud traffic.
- No unnecessary public ports.
- Replay-resistant cross-cloud requests.
- Verified TLS for PostgreSQL and for the public AWS endpoints.
- Honest documentation of TLS and mTLS limitations.

## 2. Secret inventory

All values are generated locally by `scripts/init-secrets.js` and stored only in
`.env` (which is git-ignored).

| Variable | Purpose |
|---|---|
| `POSTGRES_ADMIN_PASSWORD` | PostgreSQL bootstrap/admin |
| `AWS_DB_PASSWORD` | `aws_library` application user |
| `RENDER_DB_PASSWORD` | `render_library` application user |
| `REDIS_PASSWORD` | Redis `requirepass` |
| `CACHE_API_KEY` | Cache API `x-api-key` |
| `CONTROL_PLANE_ADMIN_TOKEN` | Weight updates and admin operations |
| `CONTROL_PLANE_SERVICE_TOKEN` | Registration, heartbeat, config, service reads |
| `CONTROL_PLANE_READ_TOKEN` | Dashboard/monitoring reads |
| `AWS_TO_RENDER_HMAC_SECRET` | AWS -> Render request signing |
| `RENDER_TO_AWS_HMAC_SECRET` | Render -> AWS request signing |
| `RENDER_SUPERVISOR_TOKEN` | Supervisor status endpoint |

`.env.example` contains only `__GENERATE__` placeholders. The init script does not
overwrite an existing `.env` and does not print secret values.

TLS private keys (`certs/ca.key`, `certs/server.key`) are also secrets. They are
generated by `deploy/tls/gen-certs.sh`, stored under the git-ignored `certs/`
directory, and never uploaded to Render.

## 3. Authentication and authorization

### Control Plane

Three independent scopes:

- **admin** (`x-admin-token`): weight updates, component deletion.
- **service** (`x-service-token`): registration, heartbeat, deregistration,
  routing/config reads, event writes.
- **read** (`x-read-token`): dashboard status, registry reads, events, alerts.

Tokens are compared with `crypto.timingSafeEqual` after a length check. Failures are
recorded as `auth_failure` events without revealing which comparison failed.

### Cache API

Every cache operation requires `x-api-key: CACHE_API_KEY`. Redis itself is never
published and only the Cache API knows the Redis password. In cloud deployment the
Cache API is reachable only through the Nginx TLS proxy on port `8445`; its direct
port `4100` is not published.

### Dashboard

The dashboard server holds `CONTROL_PLANE_READ_TOKEN` server-side. The browser calls
`/api/*` on the dashboard, and the BFF adds the read token. Weight updates require an
operator-supplied `x-admin-token`, which is forwarded to the Control Plane and kept
only in React state. It is never written to local storage or the bundle.

In cloud deployment the dashboard stays on loopback and is reached through an SSH
tunnel. It is not exposed by the Nginx proxy.

### Render supervisor

`/status` and `/supervisor/status` require `RENDER_SUPERVISOR_TOKEN` in
`x-admin-token`. The status port binds to `127.0.0.1` only.

## 4. Cross-cloud HMAC authentication

Render's ordinary public HTTPS terminates TLS at Render's edge. It does **not**
provide end-to-end sidecar mTLS. The project therefore signs the HTTP request
itself.

### Directions

| Direction | Secret | Signer | Verifier |
|---|---|---|---|
| AWS -> Render | `AWS_TO_RENDER_HMAC_SECRET` | API Gateway, Borrow Service | Render ingress |
| Render -> AWS | `RENDER_TO_AWS_HMAC_SECRET` | Book Replica Service | API Gateway |

### Headers

- `x-mesh-client`
- `x-mesh-timestamp` (milliseconds)
- `x-mesh-nonce` (UUID)
- `x-mesh-signature` (hex HMAC-SHA256)

### Canonical string

```text
client
timestamp
nonce
HTTP_METHOD
path-and-query
sha256(body)
```

Each line is joined with `\n`. The signature is:

```text
HMAC-SHA256(secret, canonicalString)
```

### Replay protection

- Timestamps older or newer than `HMAC_MAX_SKEW_MS` (default 5 minutes) are
  rejected.
- Nonces are stored in an in-memory `NonceStore` for 5 minutes and rejected if
  reused.
- The client id must match the expected direction, and Render ingress additionally
  checks an allowlist (`RENDER_INGRESS_ALLOWED_CLIENTS`, default
  `api-gateway,borrow-service`).
- Retries re-sign each attempt so a retried request never replays the previous
  nonce.

Nonce stores are per-process. In a multi-replica production deployment they would
need a shared store, but this project runs one gateway process and one Render
ingress process.

## 5. Transport security

| Connection | Local | Cloud deployment |
|---|---|---|
| Browser -> dashboard | HTTP | Loopback only; use an SSH tunnel |
| Client -> API Gateway | HTTP | HTTPS through Nginx on `8443` |
| AWS -> Render ingress | HTTP locally | HTTPS at Render edge + HMAC |
| Render -> AWS gateway | HTTP locally | HTTPS through Nginx on `8443` + HMAC |
| Render -> Control Plane | HTTP locally | HTTPS through Nginx on `8444` + service token |
| Render -> Cache API | HTTP locally | HTTPS through Nginx on `8445` + `x-api-key` |
| Services -> PostgreSQL | plaintext on a private Docker network | TLS on every TCP connection, `hostssl` required |
| Services -> Redis | Docker network | Private Docker network only; never public |
| Services -> Cache API | Docker network | Private Docker network (AWS) or HTTPS `8445` (Render) |

### AWS Nginx TLS proxy

`docker-compose.deploy.yml` adds one free Nginx container. It is the only public
entry point on EC2:

```text
8443/tcp -> api-gateway:8080
8444/tcp -> control-plane:4000
8445/tcp -> cache-api:4100
5433/tcp -> postgres:5432 (TLS to PostgreSQL)
```

The gateway, dashboard, Control Plane, Cache API, PostgreSQL, Redis, services,
sidecars, and supervisor are not published publicly. The deployment override
forces loopback binds for the management ports even if an old `.env` contains a
public bind value.

The HTTP hops from Nginx to the Node processes are plaintext inside the private
Docker network on the EC2 host. TLS terminates at Nginx. PostgreSQL is different:
Nginx opens a second TLS connection to PostgreSQL and verifies the server
certificate against the self-managed CA.

### Certificate verification

The deployment uses a free self-managed CA:

- `certs/ca.crt` is the public CA certificate.
- `certs/server.crt` is the server certificate with SANs for `postgres`,
  `localhost`, the EC2 public host, `127.0.0.1`, and the EC2 public IP.
- `certs/ca.key` and `certs/server.key` are private keys and stay on the EC2 host.

PostgreSQL clients use:

```dotenv
DB_SSL=true
DB_SSL_REJECT_UNAUTHORIZED=true
DB_SSL_CA_PATH=/etc/mesh-certs/ca.crt        # AWS containers
# or /etc/secrets/mesh-ca.crt on Render
```

Render also sets `NODE_EXTRA_CA_CERTS=/etc/secrets/mesh-ca.crt` so its outbound
HTTPS calls trust the same CA.

`shared/db.js` defaults `DB_SSL_REJECT_UNAUTHORIZED` to `true`. If it is set to
`false`, `createPool` logs a `db_tls_verification_disabled` warning. Disabling
verification is never silent.

The project does **not** claim end-to-end mTLS. No reverse tunnels are used.

## 6. Network exposure

Local stack:

- Published: `3000` dashboard, `8080` gateway, `127.0.0.1:4000` Control Plane,
  `127.0.0.1:8081` Render ingress in bundle mode.
- Not published: PostgreSQL, Redis, Cache API, all service ports, all sidecar ports,
  supervisor status port.

Render:

- One public HTTPS port assigned by Render.
- Internal sidecar ports bind to loopback inside the container.
- Public traffic must go through the ingress dispatcher.

AWS EC2:

- Public: Nginx `8443`, `8444`, `8445`, and `5433` only.
- `22` is open only to the administrator IP.
- `3000` is not opened; use an SSH tunnel.
- `8080`, `4000`, `4100`, `5432`, `6379`, `4101-4105`, `5101-5105`, and `5300`
  must not be opened.
- Restrict `8443`, `8444`, `8445`, and `5433` to the Render outbound ranges and
  administrator IPs where the lab allows it.

Render Free uses shared regional outbound IP ranges, not a dedicated per-service
IP. The ranges can be allowlisted but are shared with other Render customers, so
TLS, HMAC, API keys, and database passwords remain the real controls. Dedicated
outbound IPs are paid and are not used.

## 7. Secret handling in containers and logs

- `.dockerignore` excludes `.env`, certificates, keys, tests, docs, and logs from
  build contexts.
- Containers receive secrets at runtime through `env_file`, not baked into images.
- The logger records structured fields but never intentionally logs secret values.
- Gateway and ingress header filters remove internal auth headers before forwarding.
- HMAC signatures and nonces are not secrets, but they are not logged as values.
- Backup files may contain application data and are git-ignored; keep them private.
- Render Secret Files contain only the public CA certificate, never a private key.

## 8. Security checks performed

The integration suite checks:

- Control Plane read endpoints reject missing tokens.
- Weight updates reject missing admin tokens.
- `/cross-cloud/books` rejects unsigned, tampered, stale, and replayed requests.
- Render ingress rejects unsigned and replayed requests.
- Dashboard HTML and JS assets do not contain any configured secret value.
- Internal ports are not reachable from the host in the local stack.
- Dashboard sends `X-Content-Type-Options: nosniff` and `X-Frame-Options: DENY`.

Deployment-readiness checks performed without cloud access:

- `docker compose config` validates the base, deploy, and PostgreSQL TLS files.
- `nginx -t` validates the TLS proxy configuration with generated test
  certificates.
- `node --check` validates the modified JavaScript.
- Unit tests validate the database TLS configuration helper.

A repository scan was also run: configured secret values were searched across all
source, config, and documentation files (excluding `.env`, `node_modules`, backups,
and binary files). No secret value was found outside `.env`.

## 9. Known limitations

- In-memory nonce stores are not shared across multiple gateway or ingress replicas.
- The self-managed CA is not publicly trusted. Clients must be given `certs/ca.crt`.
- If the EC2 public host or IP changes, the server certificate must be regenerated.
  Reusing the same CA avoids re-uploading it to Render.
- Nginx is a single TLS terminator on one EC2 instance. If it fails, the public AWS
  endpoints are unavailable.
- HTTP traffic from Nginx to the Node processes is plaintext inside the private
  Docker network. PostgreSQL traffic is TLS on both hops.
- Render Free has no private networking to AWS. Cross-cloud calls use public HTTPS
  plus HMAC.
- Render Free outbound ranges are shared, not dedicated.
- The dashboard admin token is entered by the operator and sent on each weight
  update. It is not persisted, but it does pass through the dashboard BFF in memory.
- This is a college project, not a hardened production security product. Perform a
  fresh secret generation and an independent review before any public deployment.
